# Stock Predictor v12.0 開発ロードマップ：実運用への架け橋

## 1. 現状分析と課題 (v11.0 Feedback Summary)

外部AI（Gemini, Grok）による監査の結果、v11.0（PF 5.00, 勝率84%）は「シミュレーション環境の不備」による過大評価の可能性が高いことが判明しました。

### 🚨 クリティカルな課題
1.  **データ品質の欠陥**: `yfinance` の日本株データは欠損が多く、調整後終値の計算が不正確な場合がある。
2.  **市場微細構造の無視**:
    *   **板寄せ (Itayose)**: 始値・終値での約定メカニズムが考慮されていない。
    *   **値幅制限 (Price Limits)**: ストップ高/安での売買停止がシミュレートされていない。
    *   **特別気配 (Special Quotes)**: 急変動時の約定遅延・スリッページがない。
3.  **過学習とリーク**: 単純な時系列分割では、自己相関による「未来情報の漏洩（Leakage）」が発生している可能性がある。

## 2. 開発フェーズ計画

「聖杯（ありえない高成績）」を捨て、「現実的な勝てるシステム」への再構築を目指します。

### Phase 1: データインフラの刷新 (Data Infrastructure)
**目標**: 信頼できる「一次情報」への移行。
- [ ] **J-Quants API (Free/Premium) の導入**
    - `yfinance` からの脱却。
    - 公式のOHLCVデータ、分割・併合情報の取得。
- [ ] **ローカルDBの構築**
    - 取得したデータをSQLite/PostgreSQLに蓄積し、バックテストの高速化と安定化を図る。
- [ ] **データクリーニング・パイプライン**
    - 欠損値の適切な処理、株式分割の遡及修正ロジックの実装。

### Phase 2: シミュレーションの厳密化 (Realistic Simulation)
**目標**: バックテスト成績を「実運用で再現可能な数値」に補正する（PF 1.5〜2.0を目指す）。
- [ ] **値幅制限（ストップ高/安）ロジックの実装**
    - 前日終値に基づき、当日の制限値幅を計算。
    - ストップ高価格での「買い」、ストップ安価格での「売り」を禁止（約定不可とする）。
- [ ] **板寄せ・流動性制約の実装**
    - 寄付（Open）のエントリーに対して、スリッページ（またはペナルティコスト）を付加。
    - 出来高が少ない銘柄/時間帯のトレード回避フィルター。
- [ ] **昼休みギャップの考慮**
    - 前場引けと後場寄りの間の変動リスクを評価。

### Phase 3: AIモデルの高度化と検証 (Advanced AI & Validation)
**目標**: 統計的に正しい検証手法と、より強力なモデルの導入。
- [ ] **Purged Cross-Validation (CPCV) の導入**
    - 学習データとテストデータの間に「Embargo（禁止期間）」を設け、リークを完全排除。
- [ ] **LightGBM への移行**
    - Random Forest から、より高速で精度の高い勾配ブースティング決定木（GBDT）へ移行。
    - カスタム損失関数（シャープレシオ最大化など）の検討。
- [ ] **特徴量エンジニアリングの強化**
    - ボラティリティレシオ、出来高加重平均価格（VWAP）乖離率などの追加。

### Phase 4: 実運用準備 (Live Trading Prep)
**目標**: 証券会社APIとの接続検証。
- [ ] **auカブコム証券 (kabu STATION API) の調査**
    - リアルタイム板情報の取得テスト。
    - 仮想売買（Paper Trading）モードの実装。
